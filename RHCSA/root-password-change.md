
# Boot Process in RHEL9

```
+-------------------------------------------------------------------------------------+
|                                  RHEL9 Boot Process                                 |
+-------------------------------------------------------------------------------------+
|                                                                                     |
|  [1] BIOS / UEFI Firmware                                                           |
|  ---------------------------------------------------------------------------------  |
|  - Performs POST (Power-On Self Test).                                              |
|  - Detects CPU, memory, storage, peripherals.                                       |
|  - Loads Bootloader (from MBR or EFI partition).                                   |
|  - Transfers control to GRUB2.                                                     |
|                                                                                     |
|       |                                                                             |
|       v                                                                             |
|                                                                                     |
|  [2] GRUB2 (Grand Unified Bootloader v2)                                            |
|  ---------------------------------------------------------------------------------  |
|  - Located in /boot/grub2 or EFI System Partition (/boot/efi).                      |
|  - Reads /boot/grub2/grub.cfg (generated by grub2-mkconfig).                        |
|  - Displays boot menu with kernel entries.                                          |
|  - Loads two key files into memory:                                                 |
|        → vmlinuz-<kernel-version> (Kernel image)                                    |
|        → initramfs-<kernel-version>.img (Initial RAM filesystem)                    |
|  - Passes kernel parameters (from GRUB menu or /etc/default/grub).                  |
|  - Transfers control to Kernel.                                                     |
|                                                                                     |
|       |                                                                             |
|       v                                                                             |
|                                                                                     |
|  [3] Kernel (vmlinuz)                                                               |
|  ---------------------------------------------------------------------------------  |
|  - Decompresses itself into memory.                                                 |
|  - Initializes low-level hardware drivers.                                          |
|  - Mounts initramfs (Initial RAM Filesystem) as temporary root filesystem.          |
|  - Executes /init from initramfs.                                                   |
|                                                                                     |
|       |                                                                             |
|       v                                                                             |
|                                                                                     |
|  [4] initramfs (Initial RAM Filesystem)                                             |
|  ---------------------------------------------------------------------------------  |
|  - Created by Dracut tool (dracut.conf defines content).                            |
|  - Provides temporary root filesystem in memory.                                   |
|  - Contains minimal Linux environment:                                              |
|        /init        → main boot script                                              |
|        /bin, /sbin  → essential utilities                                           |
|        /lib/modules → kernel modules (e.g., ext4, LVM, RAID)                        |
|  - /init performs:                                                                  |
|        1. Loads storage and filesystem modules.                                    |
|        2. Starts udev to detect devices dynamically.                                |
|        3. Reads /etc/fstab or cmdline for root device info.                         |
|        4. Mounts the real root filesystem under /sysroot.                          |
|  - If rd.break is set → drops into emergency shell before switching root.           |
|  - Finally executes switch_root to hand over control.                               |
|                                                                                     |
|       |                                                                             |
|       v                                                                             |
|                                                                                     |
|  [5] switch_root → Real Root Filesystem (/sysroot)                                  |
|  ---------------------------------------------------------------------------------  |
|  - Unmounts initramfs and mounts real root filesystem (/).                          |
|  - Executes /sbin/init (symbolic link to systemd).                                  |
|                                                                                     |
|       |                                                                             |
|       v                                                                             |
|                                                                                     |
|  [6] systemd (PID 1)                                                                |
|  ---------------------------------------------------------------------------------  |
|  - First user-space process (replaces old SysV init).                               |
|  - Reads configuration from:                                                        |
|        /etc/systemd/system/                                                         |
|        /usr/lib/systemd/system/                                                     |
|  - Mounts remaining filesystems (/proc, /sys, /dev, /run, etc.).                    |
|  - Executes target units in sequence:                                               |
|        → basic.target → multi-user.target → graphical.target                        |
|  - Starts all configured services and daemons.                                      |
|  - Brings system to operational (login) state.                                      |
|                                                                                     |
|       |                                                                             |
|       v                                                                             |
|                                                                                     |
|  [7] Login Stage                                                                    |
|  ---------------------------------------------------------------------------------  |
|  - Display Manager (GDM) or getty runs on TTYs.                                     |
|  - Prompts user for credentials.                                                    |
|  - On login, shell (bash/zsh) is executed and environment is set.                   |
|  - System is fully up and running.                                                  |
|                                                                                     |
+-------------------------------------------------------------------------------------+
```

### 🔍 Summary Flow

```
BIOS/UEFI → GRUB2 → Kernel → initramfs (/init) → switch_root → systemd → User Login
```

### 🧠 Key Notes

* `initramfs` is temporary; it exists in memory only until the real root mounts.
* `dracut` builds initramfs automatically during kernel updates.
* `systemd` now fully manages service startup, replacing SysV init scripts.
* Kernel parameters (`rd.break`, `root=`, `ro/rw`, etc.) guide how initramfs behaves.

## Interrupt Boot Process to Break Password

Prerequisites (for the lab):

* A RHEL 9 VM you control.
* Console/VM viewer to interact with GRUB menu.

Overview of the flow:

Detailed step-by-step (commands included)

1. Reboot and enter GRUB edit mode

* Reboot the VM. When the GRUB menu appears do one of these:

  * Press `e` to edit the highlighted kernel entry (one-time change).
  * If GRUB menu doesn't show, press/hold `Shift` or `Esc` right after firmware POST until GRUB appears.
* Identify the kernel `linux` line (contains `vmlinuz-...` and a sequence of kernel cmdline options like `ro root=UUID=...`).

2. Append `rd.break` to the kernel command line

* Move to the end of that `linux`/`linux16` line and add a space then `rd.break`.
* Alternative flags (use only if you understand implications):

  * `rw init=/bin/bash` — may give a shell on the real root; less safe with SELinux.
  * `rd.break enforcing=0` — temporarily disables SELinux enforcement in some contexts (only for lab troubleshooting; not recommended for production).
* Boot with the modified line: press `Ctrl+X` or `F10` depending on GRUB.

3. You arrive at an initramfs shell

* Prompt usually looks like one of:

  * `switch_root:/#`  or  `sh-5.1#`
* The installed root is typically mounted at `/sysroot`, but it is often mounted read-only.
* Confirm with:

  ```bash
  mount | grep sysroot
  ls -l /sysroot
  cat /proc/cmdline   # verify rd.break present
  ```

4. Remount /sysroot read-write

* Run:

  ```bash
  mount -o remount,rw /sysroot
  ```
* Verify changes via `mount | grep sysroot` (look for `rw` in the options).
* If `mount` fails, check `dmesg` for errors and ensure the root device is present.

5. Bind-mount kernel pseudo-filesystems (recommended before chroot)

* Many system tools expect `/proc`, `/sys`, `/dev` to exist. Bind them into /sysroot:

  ```bash
  mount --bind /proc /sysroot/proc
  mount --bind /sys  /sysroot/sys
  mount --bind /dev  /sysroot/dev
  mount --bind /run  /sysroot/run   # sometimes helpful
  ```
* You can also copy resolv.conf if network commands are needed (rare in this flow):

  ```bash
  cp /etc/resolv.conf /sysroot/etc/resolv.conf
  ```

6. chroot into /sysroot

* Enter the installed system environment:

  ```bash
  chroot /sysroot /bin/bash
  ```
* You are now running the installed system's binaries and using its `/etc/pam.d/` and other configuration.

7. Reset the root password

* Use the standard utility:

  ```bash
  passwd root
  ```
* Follow prompts and pick a password that meets your VM’s password policy.
* If `passwd` fails due to PAM policy, ensure password complexity is met or adjust policies only in a lab.

8. Ensure SELinux contexts are repaired

* If SELinux is enabled (default on RHEL 9), create the autorelabel file so the system relabels on first full boot:

  ```bash
  touch /.autorelabel
  ```
* Alternative (advanced): run `restorecon` on specific files you changed, but `/.autorelabel` is simplest and safest.

9. Exit chroot and the initramfs shell

* Exit the chroot shell:

  ```bash
  exit   # leaves chroot
  ```
* If you are returned to initramfs shell, you may need to exit again to let dracut continue:

  ```bash
  exit
  ```
* If the system does not continue automatically, you can force a reboot from the initramfs environment (use cautiously):

  ```bash
  reboot -f
  ```

10. Let the system boot normally

* The boot should proceed. The first boot may take longer due to SELinux relabeling.
* When it finishes, log in as root with the password you set.

Verification steps after boot

* Check that root login works: `ssh`/console.
* Inspect SELinux relabel logs and AVC denials:

  ```bash
  journalctl -b | less
  ausearch -m AVC -ts today
  sealert -a /var/log/audit/audit.log   # if sealert installed (setroubleshoot)
  ```
* Check system health:

  ```bash
  systemctl status sshd
  systemctl --failed
  df -h
  ```

Caveats & advanced notes

* Encrypted root (LUKS): If your root filesystem is LUKS-encrypted, initramfs cannot mount the underlying filesystem until it has the decryption key. `rd.break` gets you into initramfs but you still must unlock LUKS (enter passphrase) to access `/sysroot` contents. Without the passphrase, you cannot change `/etc/shadow`.
* GRUB password: If GRUB is locked with a password, editing the kernel cmdline will be blocked. Use rescue ISO or VM firmware controls.
* Secure Boot: can enforce signed kernels/initramfs which may block custom kernels or unsigned initramfs images.
* SELinux: failing to relabel may cause services to misbehave. Always `touch /.autorelabel` after on-disk changes in a lab setting.

Troubleshooting common failures

* `passwd` failure: check free space (`df -h`) inside chroot; ensure `/etc/shadow` exists and is writable; check PAM messages in `/var/log/secure`.
* `mount -o remount,rw /sysroot` fails: confirm `/sysroot` is present and you are in initramfs; check `lsblk` and `blkid` to ensure disk devices exist.
* `chroot` complains about missing libraries: ensure you bind-mounted `/proc`, `/sys`, `/dev` and that the installed system has compatible `/bin/bash`.
* If the system boots to emergency.target after reboot: inspect `journalctl -b -1` to see why services failed; restore contexts or fix config files as needed.

Lab exercises (practice & confirm learning)

* Exercise A: Use `rd.break` to change `/etc/hostname` and verify it persists after boot.
* Exercise B: Rebuild initramfs with `dracut -f` and then intentionally remove an LVM module from the initramfs to simulate boot failure; restore and observe logs.
* Exercise C: Create a small encrypted root VM (LUKS) and verify that `rd.break` alone cannot bypass encryption — practice unlocking the volume within initramfs.

Security & best practice reminders

* Do not leave `/.autorelabel` file after you finish experimenting (the system handles it on next boot). If you need to cancel relabeling, reboot into rescue mode and remove the file.
* Document recovery steps and keep secure backups of critical data and LUKS headers.
